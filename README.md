# 银行间债券交易系统 - 知识库

## 项目定位

本项目知识库服务于银行间债券交易系统的产品、业务和研发团队，旨在系统化地收集、整理和共享以下领域的知识：

- **市场认知**：银行间债券市场的运行机制、参与主体与发展趋势
- **业务理解**：债券交易的完整业务链路，从询价到清算结算
- **系统设计**：交易系统的功能架构、技术架构与接口规范
- **竞争格局**：主要竞品的产品形态与差异化分析
- **生态全景**：上下游基础设施、数据服务商与合作方网络
- **合规风控**：法律法规框架与风险控制体系

知识库的内容组织以系统的两类核心业务用户为主线：

- **固收投资经理**：负责市场研判、组合管理、交易决策与指令下达
- **交易员**：负责询价执行、对手撮合、成交落地与合规留痕

这意味着，知识库不仅回答“市场和系统是什么”，也重点回答“投资经理与交易员如何协作完成交易，以及系统应该优先支持什么”。

## 核心用户定位

| 角色 | 核心目标 | 高频动作 | 关注重点 |
|------|----------|----------|----------|
| 固收投资经理 | 做出有效的投资决策并管理组合收益风险 | 研判行情、选择标的、设定价格区间、下达指令、跟踪成交后组合变化 | 收益、久期、DV01、信用风险、组合约束 |
| 交易员 | 高效完成询价、比价、成交和台账留痕 | 接收指令、IM询价、RFQ/对话报价、点击成交、反馈回报 | 执行效率、成交价格、对手方、合规留痕 |

## 知识库使用指南

### 按业务用户视角阅读

- **投资经理视角**：优先阅读「市场概述」「业务流程」「系统架构」，重点理解市场判断、组合管理、指令下达和成交反馈
- **交易员视角**：优先阅读「业务流程」「系统架构」「法规合规」，重点理解询报价、交易执行、对手管理和留痕要求

### 按团队职责阅读

- **产品经理**：重点阅读「市场概述」「业务流程」「竞品分析」，明确核心用户场景与产品边界
- **业务分析师**：重点阅读「业务流程」「法规合规」，拆解角色分工、业务规则和异常场景
- **架构师**：重点阅读「系统架构」「上下游生态」，理解系统分层、集成对象和性能边界
- **开发工程师**：重点阅读「系统架构」「业务流程」，理解主流程、核心模块和接口关系
- **测试工程师**：重点阅读「业务流程」「系统架构」「法规合规」，覆盖角色协作、合规校验和异常处理

### 文档规范

1. 所有文档使用 Markdown 格式编写
2. 每个目录下包含 `README.md` 作为模块索引
3. 文档中涉及的数据需标注来源和更新时间
4. 重要结论需标注依据，保持可追溯性
5. 涉及功能设计时，默认先说明投资经理与交易员的目标、动作和协作关系
