## 二、CFETS 接口

### 接入方式

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| **CFETS API** | CFETS提供的标准交易接口 | 交易下单、行情订阅 |
| **FIX协议** | 金融信息交换标准协议 | 跨系统标准化对接 |
| **IMIX协议** | CFETS自定义消息协议 | 交易、行情、结算 |

### 主要接口功能

#### 交易接口

| 接口 | 方向 | 说明 |
|------|------|------|
| 询价请求 | 系统 → CFETS | 发送RFQ |
| 报价回复 | CFETS → 系统 | 接收做市商报价 |
| 对话报价 | 双向 | 发起/回复对话报价 |
| 点击成交 | 系统 → CFETS | 接受报价成交 |
| 成交回报 | CFETS → 系统 | 接收成交通知 |
| 交易撤销 | 系统 → CFETS | 撤销未成交报价 |

#### 行情接口

| 接口 | 方向 | 说明 |
|------|------|------|
| 做市报价行情 | CFETS → 系统 | 做市商双边报价推送 |
| 成交行情 | CFETS → 系统 | 市场成交数据推送 |
| 最优报价 | CFETS → 系统 | 当前最优买卖报价 |
| 市场深度 | CFETS → 系统 | 多档报价深度 |

### 数据格式

**FIX消息示例（Quote Request）**：
```
8=FIX.4.4|9=...|35=R|49=SENDER|56=CFETS|
146=1|55=200001|54=1|38=10000000|40=2|10=...|
```

**关键字段映射**：

| FIX字段 | 说明 | 示例 |
|---------|------|------|
| MsgType(35) | 消息类型 | R=报价请求, S=报价, D=订单 |
| Symbol(55) | 债券代码 | 200001 |
| Side(54) | 买卖方向 | 1=买入, 2=卖出 |
| OrderQty(38) | 交易数量 | 10000000（面值） |
| Price(44) | 价格 | 99.50（净价） |

## 三、中债登（CCDC）接口

### 主要接口

| 接口 | 方向 | 说明 |
|------|------|------|
| 结算指令提交 | 系统 → CCDC | 提交DVP结算指令 |
| 结算指令查询 | 系统 → CCDC | 查询结算指令状态 |
| 结算结果通知 | CCDC → 系统 | 结算成功/失败通知 |
| 持仓查询 | 系统 → CCDC | 查询债券持仓 |
| 质押管理 | 系统 → CCDC | 质押/解押操作 |
| 对账文件 | CCDC → 系统 | 日终对账文件下载 |

### 结算指令格式

| 字段 | 说明 | 必填 |
|------|------|------|
| 结算业务类型 | 现券买卖/回购等 | 是 |
| 债券代码 | 标的债券 | 是 |
| 买卖方向 | 买入/卖出 | 是 |
| 结算面值 | 交易面值金额 | 是 |
| 结算价格 | 净价 | 是 |
| 应计利息 | 应计利息金额 | 是 |
| 结算金额 | 全价×面值 | 是 |
| 结算日期 | 约定结算日 | 是 |
| 结算方式 | DVP等 | 是 |
| 对手方 | 交易对手信息 | 是 |

### 文件传输

| 文件类型 | 方向 | 频率 | 格式 |
|----------|------|------|------|
| 日终对账文件 | CCDC → 系统 | 日终 | XML/TXT |
| 结算通知文件 | CCDC → 系统 | 实时 | XML |
| 持仓余额文件 | CCDC → 系统 | 日终 | XML/TXT |

## 四、上清所（SHCH）接口

### 主要接口

| 接口 | 方向 | 说明 |
|------|------|------|
| 结算指令提交 | 系统 → SHCH | 提交结算指令 |
| 结算状态查询 | 系统 → SHCH | 查询结算进度 |
| 结算结果通知 | SHCH → 系统 | 结算结果推送 |
| 集中清算接口 | 双向 | 衍生品集中清算 |
| 保证金管理 | 系统 → SHCH | 保证金缴纳/追加 |

### 与中债登接口的差异

| 差异点 | 中债登 | 上清所 |
|--------|--------|--------|
| 托管品种 | 国债、政策性金融债、企业债 | 短融、中票、同业存单 |
| 清算模式 | 全额逐笔 | 全额 + 集中净额 |
| 保证金 | 无（全额结算） | 有（集中清算品种） |
| 接口协议 | 自定义 | 自定义 |

## 五、IM消息对接接口（询报价核心）

> 对接QTrade/iDeal等IM工具，实现交易意向的自动采集、识别和指令下达。

### 5.1 QTrade接口

| 接口 | 方向 | 说明 |
|------|------|------|
| 消息回调 | QTrade → 系统 | 接收交易聊天消息推送 |
| 台账查询 | 系统 → QTrade | 查询AI解析后的结构化台账 |
| 台账导出 | 系统 → QTrade | 导出恒生/衡泰模板格式台账 |
| 意向指令 | 系统 → QTrade | 下达交易意向指令至内部系统 |
| 好友/对手查询 | 系统 → QTrade | 查询交易对手信息 |

**QTrade消息回调数据格式**：

```json
{
  "msgId": "QT20260330001",
  "fromUser": "trader_a@bank_a",
  "toUser": "trader_b@bank_b",
  "timestamp": "2026-03-30T09:15:30.000+08:00",
  "content": "21国开10 2.82% 5000万 出",
  "aiParsed": {
    "intent": "QUOTE_SELL",
    "bondCode": "210210.IB",
    "bondName": "21国开10",
    "direction": "SELL",
    "yieldRate": 2.82,
    "faceAmount": 50000000,
    "confidence": 0.95
  }
}
```

**QTrade台账查询响应**：

```json
{
  "ledgerId": "LG20260330001",
  "date": "2026-03-30",
  "records": [
    {
      "seqNo": 1,

      "bondName": "21国开10",
      "direction": "SELL",
      "yieldRate": 2.83,
      "faceAmount": 50000000,
```

### 5.2 iDeal接口

| 接口 | 方向 | 说明 |
|------|------|------|
| 消息订阅 | iDeal → 系统 | 订阅交易沟通消息（需授权） |
| 交易辅助 | 系统 → iDeal | 从IM直接发起对话报价/RFQ |
| 做市报价推送 | iDeal → 系统 | 做市商报价实时推送 |
| 分销管理 | 系统 → iDeal | 一级分销流程管理 |
| 成交回报关联 | iDeal → 系统 | CFETS成交单与IM消息关联 |

### 5.3 交易意向指令接口

**意向指令下达（系统 → 内部交易系统）**：

```json
{
  "instructionId": "INS20260330001",
  "source": "QTRADE",
  "sourceMsgId": "QT20260330001",
  "bondCode": "210210.IB",
  "direction": "SELL",
  "yieldRate": 2.83,
  "faceAmount": 50000000,
  "counterParty": "Bank_B",
  "settlementDate": "2026-03-31",
  "settlementMethod": "DVP",
  "trader": "trader_a",
  "createTime": "2026-03-30T09:16:30.000+08:00",
  "status": "PENDING_APPROVAL"
}
```

**意向状态跟踪**：

| 状态 | 说明 |
|------|------|
| PENDING_PARSE | AI解析中 |
| PARSED | 已解析，待确认 |
| PENDING_APPROVAL | 已确认，待审批 |
| APPROVED | 已审批，待执行 |
| SUBMITTED | 已提交至CFETS |
| DEAL_DONE | 已成交 |
| CANCELLED | 已撤销 |
| REJECTED | 已驳回 |

### 5.4 意向→成交闭环关联

```
IM消息 ──AI解析──▶ 交易意向记录 ──审批──▶ 指令下达 ──CFETS成交──▶ 成交单
  │                    │                    │                    │
  │ msgId              │ instructionId      │ cfetsOrderId       │ tradeId
  └────────────────────┴────────────────────┴────────────────────┘
                              traceId (全链路追踪ID)
```

## 六、内部系统接口

### 需对接的内部系统

| 系统 | 接口方向 | 数据交换内容 |
|------|----------|-------------|
| **核心业务系统** | 双向 | 资金调拨、账户管理 |
| **风险管理系统** | 系统 → 风控 | 交易数据、持仓数据、风险指标 |
| **估值核算系统** | 系统 → 估值 | 交易数据、持仓变动 |
| **资产负债系统** | 系统 → ALM | 债券持仓、久期、DV01 |
| **信用风险系统** | 风控 → 系统 | 授信额度、交易对手评级 |
| **合规管理系统** | 双向 | 投资限制、合规规则 |
| **报表系统** | 系统 → 报表 | 交易数据、统计报表 |
| **OA系统** | OA → 系统 | 审批流程、用户信息 |

### 内部接口规范

| 规范 | 说明 |
|------|------|
| 协议 | RESTful API (HTTP/JSON) |
| 认证 | OAuth 2.0 / API Key |
| 数据格式 | JSON |
| 字符编码 | UTF-8 |
| 时间格式 | ISO 8601 (yyyy-MM-dd'T'HH:mm:ss.SSSZ) |
| 超时设置 | 连接超时 5s，读取超时 30s |
| 重试策略 | 指数退避，最多3次 |

## 六、接口管理要求

1. **接口文档**：所有接口需维护完整的 API 文档（Swagger/OpenAPI）
2. **版本管理**：接口变更需进行版本管理，保证向后兼容
3. **监控告警**：接口调用需监控成功率和响应时间
4. **限流保护**：接口需设置合理的限流策略
5. **日志记录**：所有接口调用需记录完整的请求/响应日志
6. **应急方案**：关键接口需有手工应急处理方案
