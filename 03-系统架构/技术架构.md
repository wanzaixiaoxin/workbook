# 技术架构

> 最后更新：2026-03-30

## 一、架构设计原则

| 原则 | 说明 |
|------|------|
| **高可用** | 核心交易链路 99.99% 可用性，支持主备切换 |
| **低延迟** | 行情推送延迟 < 50ms，交易处理延迟 < 100ms |
| **高并发** | 支持峰值 1000+ 并发交易请求 |
| **可扩展** | 模块化设计，支持水平扩展 |
| **安全性** | 数据加密传输，操作审计追踪 |
| **合规性** | 满足监管对数据留存、审计的要求 |

## 三、技术选型参考

### 后端技术栈

| 组件 | 推荐选型 | 备选方案 | 选型理由 |
|------|----------|----------|----------|
| 开发语言 | Java | C++/Go | 金融领域生态成熟，人才储备充足 |
| 应用框架 | Spring Boot | Quarkus | 企业级成熟度，社区支持 |
| 微服务框架 | Spring Cloud | Dubbo | 服务治理能力完善 |
| 消息队列 | Kafka | RocketMQ | 高吞吐、低延迟，适合行情分发 |
| 缓存 | Redis Cluster | Hazelcast | 高性能KV存储，适合行情缓存 |
| 关系数据库 | PostgreSQL | MySQL | 金融级可靠性，复杂查询能力 |
| 时序数据库 | TDengine | InfluxDB | 适合金融行情数据存储 |
| 搜索引擎 | Elasticsearch | - | 日志分析、全文搜索 |
| 任务调度 | XXL-Job | Quartz | 分布式任务调度 |
| 配置中心 | Nacos | Apollo | 动态配置管理 |

### 前端技术栈

| 组件 | 推荐选型 | 选型理由 |
|------|----------|----------|
| PC交易终端 | C++ + Qt / Electron | 低延迟渲染、丰富图表 |
| Web管理台 | Vue 3 + TypeScript | 组件化开发、类型安全 |
| 图表组件 | ECharts / TradingView | 专业金融图表 |
| 通信协议 | WebSocket + REST API | 实时推送 + 请求响应 |

### 通信协议

| 场景 | 协议 | 说明 |
|------|------|------|
| 行情推送 | WebSocket / UDP组播 | 实时行情推送 |
| 交易下单 | FIX协议 / 自定义TCP | 标准化交易协议 |
| 系统内部 | gRPC / REST API | 微服务间通信 |
| 文件传输 | SFTP | 结算文件、对账文件传输 |

### 容灾要求

| 指标 | 要求 |
|------|------|
| RPO（恢复点目标） | < 1分钟 |
| RTO（恢复时间目标） | < 5分钟 |
| 数据同步 | 同城双活 + 异地灾备 |
| 切换方式 | 自动故障检测 + 手动确认切换 |

## 五、非功能需求

### 性能要求

| 指标 | 目标值 |
|------|--------|
| 行情推送延迟 | < 50ms |
| 交易下单响应 | < 100ms |
| 合规检查响应 | < 50ms |
| 并发交易处理 | 1000+ TPS |
| 系统可用性 | 99.99% |
| 日处理交易量 | 100万笔+ |

### 安全要求

| 方面 | 要求 |
|------|------|
| 传输加密 | TLS 1.2+ |
| 数据加密 | 敏感字段加密存储 |
| 身份认证 | 双因素认证 |
| 操作审计 | 全操作日志留存 |
| 数据留存 | 交易数据留存不少于 20 年 |
| 网络隔离 | 交易网段与管理网段隔离 |

### 合规要求

- 满足央行对交易系统的技术规范要求
- 支持监管数据报送
- 完整的审计追踪能力
- 数据不可篡改（区块链或数字签名）
