# 市场参与者生态

> 最后更新：2026-03-30

## 一、系统核心用户定位

银行间债券市场的参与主体很多，但对交易系统而言，最高频、最核心的前台使用者通常集中在机构内部的两类角色：固收投资经理和交易员。前者负责投资决策与组合管理，后者负责询价执行与成交落地。

| 机构类型 | 典型前台角色 | 系统重点支持场景 |
|------|------|------|
| 商业银行 / 理财子公司 | 投资经理、交易员 | 配置交易、流动性管理、回购、做市 |
| 证券公司 / 券商资管 | 投资经理、交易员 | 波段交易、询报价、一级投标、策略执行 |
| 基金公司 / 保险机构 | 投资经理、交易员 | 组合配置、风险约束下执行、估值与合规跟踪 |
| 做市机构 | 做市交易员、头寸负责人 | 双边报价、库存管理、点击成交、对冲 |

### 为什么要先区分“市场参与者”和“系统核心用户”？

- **市场参与者** 决定系统要适配哪些机构类型、业务资格和监管要求
- **系统核心用户** 决定前台产品的主流程、页面结构、权限边界和数据闭环
- 对知识库和产品设计而言，应先围绕投资经理与交易员的高频链路组织内容，再向外延展到中后台协同和机构差异

## 三、核心参与主体详解

### 1. 商业银行

**角色定位**：市场最大的参与群体，既是投资者也是融资方。

**业务场景**：
- **投资配置**：将债券作为资产配置的重要品种，匹配资产负债管理需求
- **自营交易**：通过波段操作、利差交易获取收益
- **做市业务**：为市场提供流动性，赚取买卖价差
- **代客交易**：为对公客户提供债券交易服务
- **发行融资**：发行金融债、同业存单等筹集资金

**关键需求**：
- 交易系统需支持多种交易策略（配置型、交易型、套利型）
- 需与内部资产负债管理系统、风险管理系统深度集成
- 对交易执行速度和合规风控要求极高

### 2. 证券公司

**角色定位**：市场最活跃的交易型机构之一，兼具经纪、自营和承销职能。

**业务场景**：
- **自营交易**：以赚取价差为目的的积极交易
- **经纪业务**：为机构客户提供交易通道和执行服务
- **承销业务**：作为主承销商或联席承销商参与债券发行
- **做市业务**：部分券商获批做市商资格

**关键需求**：
- 交易系统需支持高频交易、算法交易
- 需要强大的行情分析和策略回测功能
- 对交易效率和信息管理要求高

### 3. 基金公司 / 理财子公司

**角色定位**：以产品形式参与市场，管理受托资金进行债券投资。

**业务场景**：
- **产品投资**：按基金合同/产品说明书进行债券配置
- **流动性管理**：货币基金、短债基金的日常申购赎回管理
- **指数跟踪**：债券指数基金的被动投资

**关键需求**：
- 支持多产品/多账户独立管理
- 需与估值系统、TA系统对接
- 对交易合规（投资限制、集中度等）要求严格

### 4. 保险机构

**角色定位**：长期限资金配置者，偏好高信用等级长久期债券。

**业务场景**：
- **资产负债匹配**：配置长久期债券匹配保险负债
- **收益增强**：在信用风险可控前提下获取较高收益

**关键需求**：
- 支持长期限持有到期的配置型交易
- 与偿付能力管理系统集成
- 信用风险评估要求高

### 5. 做市商

**角色定位**：经央行批准，在银行间债券市场持续提供双边报价的市场核心流动性提供者。

**准入条件**：
- 需经中国人民银行审批认定
- 注册资本/净资本需满足最低要求
- 具备健全的内部管理制度和风险控制体系
- 具备相应的技术系统和专业人员

**做市商分类**：

| 类型 | 说明 | 代表机构 |
|------|------|----------|
| **银行间债券市场做市商** | 央行正式批准，有义务持续双边报价 | 工行、农行、中行、建行、交行、国开行等 |
| **尝试做市机构** | 经CFETS备案，自愿尝试做市业务 | 部分股份制银行、城商行 |
| **债券通做市商** | 为债券通境外投资者提供做市服务 | 具备债券通做市资格的银行和券商 |

**义务与权利**：

| 义务 | 权利 |
|------|------|
| 持续提供双边报价（买卖双向） | 获得做市商专属交易工具和信息 |
| 报价价差不超过规定范围 | 可参与央行公开市场操作一级交易商优选 |
| 满足最低报价时长要求 | 享有CFETS费用减免 |
| 定期提交做市报告 | 可优先参与债券承销 |

**业务场景**：
- **双边报价**：持续发布特定债券的买入价和卖出价
- **流动性管理**：通过买卖价差获利，同时管理库存风险
- **对冲操作**：通过利率互换、国债期货等工具对冲做市头寸风险

**关键需求**：
- 自动化报价策略（根据库存、市场波动自动调整报价）
- 实时库存监控与对冲管理
- 极低的报价更新延迟
- 点击成交的快速响应能力

### 6. 货币经纪商

**角色定位**：经央行批准，在银行间市场为金融机构提供经纪中介服务的专业机构，本身不参与交易，不承担交易风险。

**准入条件**：
- 需经中国人民银行审批
- 可为中外合资或外商独资形式
- 需具备全球货币经纪经验（通常为国际货币经纪集团在华子公司）

**持牌货币经纪公司**：

| 公司 | 背景 |
|------|------|
| **上海国利货币经纪** | 国内外合资 |
| **上海国际货币经纪** | 国内外合资 |
| **平安利顺国际货币经纪** | 平安集团旗下 |
| **中诚宝捷思货币经纪** | 国内外合资 |
| **天津信唐货币经纪** | 国内外合资 |
| **上田八木货币经纪（中国）** | 外商独资（2021年获批开业，全国首家外商独资货币经纪公司） |

**业务范围**：

| 业务 | 说明 |
|------|------|
| **债券现券经纪** | 为买卖双方撮合成交，传递报价信息 |
| **回购经纪** | 为正逆回购双方匹配资金和质押品需求 |
| **利率互换经纪** | 为IRS交易双方提供撮合服务 |
| **同业拆借经纪** | 为资金拆借双方提供中介 |
| **外汇经纪** | 为外汇交易提供撮合 |

**运作模式**：

```
金融机构A                  货币经纪商                 金融机构B
  │                          │                          │
  │── 报价意向 ──────────▶│                          │
  │  （买入某债券）          │                          │
  │                          │── 寻找对手 ──────────▶│
  │                          │  （询问卖出意向）         │
  │                          │◀── 报价回复 ──────────│
  │                          │  （卖出价格）             │
  │◀── 传递报价 ──────────│                          │
  │  （对手方卖出价）        │                          │
  │── 确认成交 ──────────▶│── 转达确认 ──────────▶│
  │                          │                          │
  │     交易双方直接结算（经纪商不参与资金和债券交收）   │
```

**价值与特点**：
- **匿名性**：交易双方在成交前互不知道对手方身份
- **不承担风险**：经纪商仅撮合，不参与资金和债券交收
- **信息聚合**：汇聚多家机构的报价意向，提高匹配效率
- **全球网络**：国际货币经纪集团可连接境内外市场

**关键需求**：
- 高效的报价管理和匹配系统
- 支持多品种、多期限的经纪业务
- 匿名交易机制
- 快速的报价传递和信息分发

## 七、IM工具对接（公司已获取接口开发权）

> 公司业务核心依赖IM工具（iDeal、QTrade、腾讯企点通）进行询价交易，约80%以上现券交易始于IM沟通。

| IM工具 | 接口类型 | 核心能力 |
|--------|----------|---------|
| **iDeal** | CFETS iDeal实时上下行接口 | 消息收发、交易联动、CFETS系统直连 |
| **QTrade** | 腾讯QQ后台接口 | 消息收发、AI语义识别、台账导出、直连恒生/衡泰 |
| **腾讯企点通** | 腾讯QQ后台接口 | 消息收发、合规沟通、权限管理 |

**技术实现要求**：
- 消息实时上下行：接口需支持消息实时推送，延迟不超过1秒
- 消息格式兼容：询价消息格式需同时兼容iDeal、QTrade、腾讯企点通
- 三端聚合：CS客户端需统一聚合三个聊天器的消息，支持跨聊天器查看和管理
- 行情联动：将实时行情同步推送至聊天界面
- NLP集成：对接QTrade的AI语义识别模型，或自建NLP模型提取交易要素

## 八、经纪商API对接（六家，公司已获取行情牌照）

| 对接内容 | 说明 |
|----------|------|
| **行情订阅** | 六家经纪商实时报价、成交行情 |
| **询价请求** | 向经纪商提交询价（债券/方向/数量） |
| **成交确认** | 接收经纪商Dealing Slip成交确认单 |
| **比价聚合** | 多家经纪商报价对比展示 |

**技术实现要求**：
- 六家经纪商接口需统一抽象，屏蔽差异
- 行情数据需实时聚合，支持按券种、期限、收益率筛选
- 询价消息需与iDeal、QTrade、腾讯企点通双向透传
