# 交易流程

> 最后更新：2026-03-30

## 一、交易流程总览

> 现券买卖是银行间债券市场最主要的交易类型，完整流程涵盖：**行情查看 → 询价谈判 → 下单成交 → 成交回执 → 交易确认 → 清算结算** 六大环节。

```mermaid
graph LR
    subgraph 前台
        A["① 行情查看<br>做市商双边报价<br>市场成交/估值<br>收益率曲线"]
        B["② 询价谈判<br>IM沟通(QTrade/iDeal)<br>RFQ请求报价<br>多对手比价"]
        C["③ 下单成交<br>CFETS对话报价<br>点击成交/匿名撮合<br>合规检查→匹配成交"]
    end
    subgraph 中台
        D["④ 成交回执<br>CFETS成交回报<br>生成成交单号<br>推送双方交易系统"]
    end
    subgraph 后台
        E["⑤ 交易确认<br>成交单要素核对<br>合规审查<br>确认书发送"]
        F["⑥ 清算结算<br>DVP交割<br>资金划拨/债券过户<br>详见清算结算文档"]
    end

    A --> B --> C --> D --> E --> F
```

## 二、核心用户角色

> 系统的主要使用者是固收业务的投资经理和交易员，两者职责明确、协作紧密。

### 角色分工

| 维度       | 投资经理（PM）                | 交易员（Trader）                  |
| -------- | ----------------------- | ---------------------------- |
| **核心职责** | 制定投资策略、组合管理             | 执行交易指令、询价谈判                  |
| **日常工作** | 研判市场走势、决定买卖方向和仓位        | 根据指令询价、寻找对手、执行交易             |
| **关注重点** | 组合收益、久期、利差、信用风险         | 成交效率、执行价格、对手方关系              |
| **系统操作** | 下达/修改/撤销交易指令、查看组合持仓     | 接收指令→询价→下单→反馈成交              |
| **决策权限** | 决定"买什么、买多少、什么价位区间"      | 决定"找谁买、以什么具体价格成交"            |
| **风控视角** | 组合层面风险限额、合规约束           | 单笔交易合规检查、对手授信                |
| **行情分析** | 收益率曲线、估值、信用利差、市场成交分布    | 做市商双边报价（Bid/Ask）、盘口深度、最新成交价量 |
| **分析输出** | 交易指令（债券/方向/数量/价格区间/紧迫度） | 执行策略（找谁询价、何时出手、分拆还是一次性）      |

### 投资经理→交易员协作流程

```mermaid
sequenceDiagram
    participant PM as 投资经理（PM）
    participant T as 交易员（Trader）

    PM->>PM: 1. 研判市场/组合分析
    Note over PM: 行情、估值、利差
    PM->>T: 2. 下达交易指令
    Note over PM,T: 指令池：债券/方向/数量/价格区间/紧迫度
    T->>T: 3. 接收指令
    Note over T: 查看指令详情、评估可执行性
    T->>T: 4. 询价执行
    Note over T: QTrade/iDeal询价、多对手比价、达成交易意向
    T->>T: 5. CFETS成交
    Note over T: 录入对话报价、合规检查→确认成交
    T->>PM: 6. 反馈成交结果
    Note over PM,T: 价格/数量/对手方
    PM->>PM: 7. 确认成交反馈
    Note over PM: 更新组合持仓
    PM->>PM: 8. 组合再平衡
    Note over PM: 调整仓位/下达新指令
```

## 三、交易环节详解

### 环节1：行情查看与分析

> 投资经理和交易员在行情查看阶段各有侧重：投资经理从组合视角决策"要不要交易"，交易员从市场微观结构判断"能不能成交"。

**系统功能需求**：

- 实时行情展示（做市商报价、成交行情）
- 收益率曲线展示与分析
- 债券估值查询（中债估值）
- 自选债券列表管理
- 支持从行情分析结果直接生成候选交易指令或加入观察列表

### 环节2：询价与报价（核心环节）

> 银行间债券市场是典型的OTC市场，交易高度依赖询报价环节。
> 据估计，约80%以上的现券交易始于IM沟通（QTrade/iDeal/企微等），最终在CFETS本币系统完成成交。

**当前产品中的工作台闭环**：

- 聊天或任务驱动的交易需求先进入“我的任务”或“我的行情”
- NLP 自动识别债券、方向、价格、数量等关键要素，沉淀为结构化私域行情
- 交易员在工作台内继续议价、群发或发起成交，并保留聊天回溯链路
- 议价达成后生成待确认单据，再与下游交易系统衔接

#### 2.1 询报价体系

> 银行间债券市场是典型的OTC市场，约80%以上的现券交易始于IM沟通（QTrade/iDeal），最终在CFETS本币系统完成成交。

| 交易路径     | 交易机制        | 匿名性  | 适用场景          |
| -------- | ----------- | ---- | ------------- |
| 直接交易     | 一对一询价谈判     | 双方已知 | 大额、非标券、需要谈判   |
| 做市商交易    | 点击成交做市商双边报价 | 双方已知 | 标准券、快速成交      |
| 经纪商交易    | 经纪商居间撮合     | 匿名   | 大额、不想暴露身份     |
| X-Bond交易 | 电子匿名撮合      | 完全匿名 | 现券买卖、流动性好的利率债 |
| X-Repo交易 | 电子匿名撮合      | 完全匿名 | 质押式回购、资金交易    |

##### 直接交易

> 交易员通过IM工具（QTrade/iDeal）直接与对手方询价，达成意向后在CFETS通过对话报价完成成交。

```mermaid
sequenceDiagram
    participant A as 交易员A（发起方）
    participant IM as QTrade/iDeal
    participant B as 交易员B（对手方）
    participant C as CFETS

    A->>IM: ① 发起询价（债券代码/方向/数量/期望价格）
    IM-->>B: ② 消息送达（交易员B收到询价）
    B->>IM: ③ 回复报价（还价/接受）
    IM-->>A: ④ 报价送达（交易员A收到报价）
    A->>IM: ⑤ 多轮谈判（价格/数量协商）
    IM-->>B: ⑥ 谈判消息送达
    B->>IM: ⑦ 达成意向（双方就价格数量达成一致）
    IM-->>A: ⑧ 意向确认
    A->>C: ⑨ 提交对话报价（录入完整交易要素）
    C-->>B: ⑩ 对话报价通知（对手方收到待确认报价）
    B->>C: ⑪ 确认对话报价（对手方在CFETS确认）
    C-->>A: ⑫ CFETS成交回报（正式成交凭证）
    C-->>B: ⑫' CFETS成交回报（正式成交凭证）
```

##### 做市商交易

> 做市商在CFETS上持续发布双边报价（Bid/Ask），交易员可直接点击做市商报价完成成交，无需谈判。

```mermaid
sequenceDiagram
    participant MM as 做市商
    participant C as CFETS
    participant A as 交易员A（机构客户）

    MM->>C: ① 持续发布双边报价（Bid/Ask价格+数量，真实可成交）
    C-->>A: ② 做市商报价推送（实时展示双边报价，含做市商资质标识）
    A->>A: ③ 评估报价合理性（比价/自身授信/内部风控检查）
    A->>C: ④ 点击成交（选择做市商报价，提交成交请求，明确买卖方向）
    C->>MM: ⑤ 成交通知（推送成交要素，做市商确认无异议）
    C-->>A: ⑥ CFETS成交回报（正式成交凭证，法律有效依据）
    C-->>MM: ⑥' CFETS成交回报（正式成交凭证，用于台账登记/风控）
    MM->>C: ⑦ 提交清算交割指令（配合CFETS完成资金/债券交割）
    A->>C: ⑦' 提交清算交割指令（配合CFETS完成资金/债券交割）
```

##### 经纪商交易

> 通过货币经纪商撮合成交，交易双方互不知晓对方身份。

```mermaid
sequenceDiagram
    participant A as 交易员A（机构A）
    participant Bk as 货币经纪商
    participant B as 交易员B（机构B）
    participant C as CFETS

    A->>Bk: ① 提交询价请求（债券代码/方向/数量）
    Bk->>B: ② 寻找对手/询价（询问卖出/买入意向）
    B-->>Bk: ③ 报价回复（对手方价格/数量）
    Bk-->>A: ④ 传递报价（对手方卖出/买入价）
    A->>Bk: ⑤ 确认成交（接受报价，达成意向）
    Bk->>B: ⑤' 转达确认（告知B，达成意向）
    Bk-->>A: ⑥ 发送Dealing Slip（成交确认单，留痕）
    Bk-->>B: ⑥' 发送Dealing Slip（成交确认单，留痕）
    A->>C: ⑦ 自行录入CFETS（录入成交要素，发起匹配）
    B->>C: ⑦' 自行录入CFETS（录入成交要素，确认匹配）
    B->>C: ⑧ 双方匹配成交（CFETS校验要素）
    C-->>A: ⑨ CFETS成交回报（正式成交凭证，合法有效）
    C-->>B: ⑨ CFETS成交回报（正式成交凭证，合法有效）
    C-->>Bk: ⑨ CFETS成交回报
```

##### X-Bond交易

> 通过CFETS X-Bond电子平台进行匿名撮合成交，适合标准化、流动性较好的现券买卖。

```mermaid
sequenceDiagram
    participant A as 交易员A（匿名）
    participant C as CFETS X-Bond
    participant B as 交易员B（匿名）

    C-->>A: ① X-Bond行情推送（匿名双边报价/成交数据）
    C-->>B: ①' X-Bond行情推送
    A->>C: ② 提交限价订单（债券/方向/价格/数量/订单类型）
    B->>C: ③ 提交限价订单（反向委托，价格匹配）
    C->>C: ④ 匿名撮合引擎（价格优先/时间优先，自动匹配）
    C-->>A: ⑤ 撮合成交回报（揭示对手方身份+成交要素）
    C-->>B: ⑤' 撮合成交回报（揭示对手方身份+成交要素）
    A->>C: ⑥ 提交清算交割指令（DVP券款对付）
    B->>C: ⑥' 提交清算交割指令（DVP券款对付）
```

##### X-Repo交易

> 通过CFETS X-Repo电子平台进行质押式回购的匿名撮合成交，支持自动选券和质押率管理。

```mermaid
sequenceDiagram
    participant A as 交易员A（资金融入方）
    participant C as CFETS X-Repo
    participant B as 交易员B（资金融出方）

    C-->>A: ① X-Repo行情推送（回购利率/期限/成交数据）
    C-->>B: ①' X-Repo行情推送
    A->>A: ② 设定回购参数（利率/期限/质押券要求/融资金额）
    A->>C: ③ 提交回购订单（正回购，融入资金+质押券）
    B->>C: ④ 提交回购订单（逆回购，融出资金，匹配利率/期限）
    C->>C: ⑤ 匿名撮合引擎（利率优先/期限匹配）
    C->>C: ⑥ 质押券计算与分配（自动选券/质押率/折算比例）
    C-->>A: ⑦ 撮合成交回报（揭示对手方+回购要素+质押券清单）
    C-->>B: ⑦' 撮合成交回报（揭示对手方+回购要素+质押券清单）
    A->>C: ⑧ 首期交割指令（DVP：质押券过户+资金划拨）
    B->>C: ⑧' 首期交割指令（DVP：质押券过户+资金划拨）
    Note over A,C: 回购存续期（逐日盯市，质押券市值监控）
    C-->>A: ⑨ 到期购回通知（返还资金+利息，赎回质押券）
    C-->>B: ⑨' 到期购回通知
```

**交易要素**：

| 要素   | 现券买卖    | 质押式回购    | 债券借贷    |
| ---- | ------- | -------- | ------- |
| 债券代码 | ✅       | ✅（质押券）   | ✅（标的券）  |
| 交易方向 | 买入/卖出   | 正/逆回购    | 借入/借出   |
| 价格   | 净价或收益率  | 回购利率(%)  | 借贷费率(%) |
| 数量   | 面值金额    | 融资金额     | 标的券面值   |
| 结算日  | T+0/T+1 | 首次/到期结算日 | 起息/到期日  |
| 结算方式 | DVP     | DVP      | 券券交割    |
| 质押品  | —       | 质押券列表    | 质押券(可选) |

#### 2.2 iDeal在询报价中的角色

CFETS iDeal是交易中心推出的官方合规IM工具，深度集成CFETS交易系统：

- **实名认证**：所有用户经CFETS实名认证，与机构交易员身份绑定
- **合规留痕**：所有沟通信息自动留痕，满足监管审计要求
- **交易辅助**：支持从IM沟通直接发起对话报价/RFQ，无需切换系统
- **做市报价推送**：做市商报价实时推送至IM窗口
- **一级分销**：支持iDeal分销功能，债券承销分销全流程线上化
- **与QTrade竞争**：2021年交易商协会规范IM工具后，iDeal与QTrade形成双寡头格局

### 环节3：下单与成交

**合规检查（交易前）**：

- 交易对手授信额度检查
- 投资范围检查
- 集中度限制检查
- 停牌/发行限制检查
- 交易权限检查

**系统功能需求**：

- 交易要素录入与校验
- 交易前合规检查引擎
- 价格/利率合理性校验
- 交易确认与成交回报
- 成交通知推送

## 五、交易执行状态机

> 所有交易路径最终都需经过CFETS完成成交确认。CFETS是银行间债券市场的法定交易平台，成交回报是交易达成的法定依据。

### 5.1 CFETS交互全景

```mermaid
graph TD
    subgraph 中台
        TASK[任务承接]
        EXEC[交易执行]
    end

    subgraph CFETS交易中心
        DIALOG[对话报价]
        CLICK[点击成交]
        XBOND_MATCH[X-Bond撮合]
        XREPO_MATCH[X-Repo撮合]
        CONFIRM[成交确认]
        REPORT[成交回报]
    end

    subgraph 经纪商
        BROKER_SYS[经纪商撮合]
    end

    TASK --> EXEC
    EXEC -->|直接交易| DIALOG
    EXEC -->|做市商交易| CLICK
    EXEC -->|X-Bond交易| XBOND_MATCH
    EXEC -->|X-Repo交易| XREPO_MATCH
    EXEC -->|经纪商交易| BROKER_SYS

    DIALOG --> CONFIRM
    CLICK --> CONFIRM
    XBOND_MATCH --> CONFIRM
    XREPO_MATCH --> CONFIRM
    BROKER_SYS -->|CFETS录入| CONFIRM

    CONFIRM --> REPORT
    REPORT -->|成交回报| EXEC
    EXEC -->|状态同步| TASK
```

### 5.2 直接交易状态机

> 双方在IM上谈判达成意向后，一方在CFETS提交对话报价，对手方在CFETS上确认或拒绝。

```mermaid
graph LR
    READY[待询价] -->|发起询价| INQUIRING[询价中]
    INQUIRING -->|收到报价| QUOTING[报价中]
    QUOTING -->|达成意向| INTENT[意向达成]
    INTENT -->|提交CFETS对话报价| CFETS_SUBMIT[CFETS待确认]
    CFETS_SUBMIT -->|对手方确认| CFETS_CONFIRMED[CFETS已确认]
    CFETS_CONFIRMED -->|收到成交回报| DONE[已成交]
    CFETS_SUBMIT -->|对手方拒绝| INTENT
    CFETS_SUBMIT -->|超时未确认| INTENT
```

### 5.3 经纪商交易状态机

> 通过经纪商居间撮合，经纪商确认成交后代为在CFETS录入，双方无需互相确认。

```mermaid
graph LR
    READY[待询价] -->|提交经纪商| BROKER_INQ[经纪商询价中]
    BROKER_INQ -->|经纪商反馈报价| BROKER_QUOTE[经纪商报价中]
    BROKER_QUOTE -->|确认接受报价| BROKER_DEAL[经纪商成交]
    BROKER_DEAL -->|经纪商录入CFETS| CFETS_CONFIRMED[CFETS已确认]
    CFETS_CONFIRMED -->|收到成交回报| DONE[已成交]
    BROKER_QUOTE -->|拒绝/经纪商回复无成交| BROKER_INQ
```

### 5.4 电子交易状态机（做市商/X-Bond/X-Repo）

```mermaid
graph LR
    READY[待下单] -->|提交CFETS| CFETS_PENDING[CFETS挂单中]
```

### 8.3 异常成交处理

| 异常类型  | 处理策略               |
| ----- | ------------------ |
| 价格异常  | 标记为偏离成交，触发合规审核     |
