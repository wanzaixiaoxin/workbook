## 二、交易环节详解

### 环节1：行情查看与分析

**交易员操作**：
- 查看做市商双边报价（Bid/Ask）
- 查看市场成交行情（最新成交价、成交量）
- 查看收益率曲线（国债、政策性金融债）
- 分析资金面状况（回购利率走势）
- 查看相关资讯（宏观经济、政策动向）

**系统功能需求**：
- 实时行情展示（做市商报价、成交行情）
- 收益率曲线展示与分析
- 历史行情查询与图表分析
- 债券估值查询（中债估值）
- 自选债券列表管理

### 环节2：询价与报价

#### 询价交易模式（主要模式）

**RFQ（Request For Quote）流程**：

```
询价方                           做市商/交易对手
  │                                  │
  │──── 1.发送询价请求 ────────────▶│  债券代码、方向、数量
  │                                  │
  │◀─── 2.回复报价 ────────────────│  价格/利率、有效期
  │                                  │
  │──── 3.接受报价/继续谈判 ───────▶│
  │                                  │
  │──── 4.确认成交 ───────────────▶│  双方确认
  │                                  │
```

**对话报价流程**：

```
交易员A                           交易员B
  │                                  │
  │──── 1.发起对话报价 ───────────▶│  含交易要素
  │                                  │
  │◀─── 2.还价/接受 ──────────────│
  │                                  │
  │──── 3.确认/再还价 ───────────▶│
  │                                  │
  │     ... 多轮谈判 ...              │
  │                                  │
  │     双方确认成交                  │
```

#### 点击成交模式

- 做市商提供持续双边报价
- 交易员点击报价即可成交
- 适用于流动性较好的活跃券

**系统功能需求**：
- RFQ 发送与管理
- 对话报价（即时通讯+报价）
- 点击成交功能
- 报价有效期管理
- 多对手方询价管理
- 报价历史记录

### 环节3：下单与成交

**交易要素**：

| 要素 | 现券买卖 | 质押式回购 |
|------|----------|------------|
| 债券代码 | ✅ | ✅（质押券） |
| 交易方向 | 买入/卖出 | 正回购/逆回购 |
| 价格/利率 | 净价（元/百元面值） | 回购利率（%） |
| 交易数量 | 面值金额 | 融资金额 |
| 结算日期 | T+0/T+1 | 首次结算日 |
| 到期日期 | - | 到期结算日 |
| 结算方式 | DVP | DVP |
| 交易对手 | ✅ | ✅ |

**合规检查（交易前）**：
- 交易对手授信额度检查
- 投资范围检查
- 集中度限制检查
- 停牌/发行限制检查
- 交易权限检查

**系统功能需求**：
- 交易要素录入与校验
- 交易前合规检查引擎
- 价格/利率合理性校验
- 交易确认与成交回报
- 成交通知推送

### 环节4：交易确认

**交易确认流程**：

```
成交数据
    │
    ▼
┌──────────┐     ┌──────────┐     ┌──────────┐
│ 成交匹配  │────▶│ 交易复核  │────▶│ 确认发送  │
│ 要素核对  │     │ 中台审核  │     │ 确认给对手 │
└──────────┘     └──────────┘     └──────────┘
                                         │
                                         ▼
                                  ┌──────────┐
                                  │ 确认回报  │
                                  │ 对手确认  │
                                  └──────────┘
```

**系统功能需求**：
- 成交单生成与管理
- 交易复核工作流
- 交易确认书生成与发送
- 确认状态跟踪
- 异常交易处理

## 三、特殊交易场景

### 1. 大额交易

- 单笔交易金额较大时，需分拆执行以降低市场冲击
- 系统需支持大额交易的分批下单与统一管理
- 需要算法交易支持（TWAP/VWAP等）

### 2. 跨市场交易

- 银行间市场与交易所市场间的跨市场交易
- 需处理不同市场的交易时间、结算规则差异
- 涉及不同托管机构间的债券转托管

### 3. 回购到期续做

- 回购到期后自动发起新的回购交易
- 系统需支持到期提醒与续做工作流
- 需要考虑质押品的滚动管理

### 4. 做市商双边报价

- 做市商需持续提供买卖双边报价
- 系统需支持自动报价策略
- 需实时监控持仓和风险敞口

## 四、交易时间

| 时段 | 时间 | 说明 |
|------|------|------|
| 开盘前 | 8:30 - 9:00 | 系统准备，查询行情 |
| 上午交易 | 9:00 - 12:00 | 主要交易时段 |
| 午间 | 12:00 - 13:30 | 休市 |
| 下午交易 | 13:30 - 16:30 | 主要交易时段 |
| 交易后处理 | 16:30 - 17:00 | 结算指令发送 |
| 夜间 | 17:00 之后 | 部分品种可延长交易 |

> **注意**：具体交易时间以 CFETS 公告为准，节假日安排另行通知。

## 五、对交易系统设计的启示

1. **流程自动化**：从询价到结算的流程需尽量自动化，减少人工干预
2. **合规前置**：交易前合规检查必须实时完成，不影响交易效率
3. **多模式支持**：需同时支持询价、点击成交、RFQ等多种交易模式
4. **实时风控**：交易过程中需实时监控风险敞口
5. **审计追踪**：所有操作需记录完整的审计日志
6. **异常处理**：需支持交易撤销、修改、结算失败等异常场景
