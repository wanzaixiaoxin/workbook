## 二、交易环节详解

### 环节1：行情查看与分析

**交易员操作**：
- 查看做市商双边报价（Bid/Ask）
- 查看市场成交行情（最新成交价、成交量）
- 查看收益率曲线（国债、政策性金融债）
- 分析资金面状况（回购利率走势）
- 查看相关资讯（宏观经济、政策动向）

**系统功能需求**：
- 实时行情展示（做市商报价、成交行情）
- 收益率曲线展示与分析
- 历史行情查询与图表分析
- 债券估值查询（中债估值）
- 自选债券列表管理

### 环节2：询价与报价（核心环节）

> 银行间债券市场是典型的OTC市场，交易高度依赖询报价环节。
> 据估计，约80%以上的现券交易始于IM沟通（QTrade/iDeal/企微等），最终在CFETS本币系统完成成交。

#### 2.1 询报价体系全景

```
┌──────────────────────────────────────────────────────────────────┐
│                        询报价达成路径                             │

│ 询价成交     │  匿名点击    │  点击成交     │   请求报价          │
│              │              │              │                    │
│ QTrade/iDeal │ 交易中心     │ 做市商双边   │ 向指定对手          │
│ 达成意向     │ 匿名撮合     │ 报价引擎     │ 发送询价请求        │

├──────────────┼──────────────┼──────────────┼────────────────────┤

```

#### 2.2 路径A：IM沟通达成交易意向（最主流）

这是银行间债券市场最核心、最典型的交易达成方式。

**完整业务流程**：

```
┌─────────────────────────────────────────────────────────────────────┐
│              IM沟通 → 交易意向达成 → CFETS录入成交                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Step 1: 行情获取                                                   │
│  ┌──────────┐                                                       │
│  │ QB/森浦   │──▶ 查看做市商双边报价、市场成交、估值                 │
│  │ Wind/CFETS│──▶ 确定目标债券和合理价格区间                          │
│  └──────────┘                                                       │
│       │                                                             │
│       ▼                                                             │
│  Step 2: IM询价（QTrade/iDeal/企微）                                │
│  ┌──────────────────────────────────────────────┐                   │
│  │ 交易员A ──▶ "21国开10 2.82% 5000万 出"  ──▶ 交易员B            │
│  │                                                │                 │
│  │ 交易员B ──▶ "2.83% 可以"               ──▶ 交易员A              │
│  │                                                │                 │
│  │ 交易员A ──▶ "行，2.83% 5000万 成"      ──▶ 交易员B              │
│  └──────────────────────────────────────────────┘                   │
│       │                                                             │
│       ▼                                                             │
│  Step 3: AI辅助（QTrade现券台账）                                   │
│  ┌──────────────────────────────────────────────┐                   │
│  │ AI自动识别：                                  │                 │
│  │  · 债券代码 → 21国开10 (210210.IB)            │                 │
│  │  · 交易方向 → 卖出                            │                 │
│  │  · 成交价格 → 2.83%                           │                 │
│  │  · 成交数量 → 5000万面值                      │                 │
│  │  · 意图判定 → 成交                            │                 │
│  │ 自动生成标准化台账记录                         │                 │
│  └──────────────────────────────────────────────┘                   │
│       │                                                             │
│       ▼                                                             │
│  Step 4: 台账导出/指令下达                                          │
│  ┌──────────────────────────────────────────────┐                   │
│  │ 方式1: QTrade导出恒生/衡泰模板 → 手动录入内部系统               │
│  │ 方式2: QTrade交易意向指令 → 直连恒生O45/衡泰xIR                │
│  │ 方式3: 手动整理台账 → 在CFETS本币系统录入对话报价               │
│  └──────────────────────────────────────────────┘                   │
│       │                                                             │
│       ▼                                                             │
│  Step 5: CFETS本币系统录入成交                                      │
│  ┌──────────────────────────────────────────────┐                   │
│  │ 在CFETS交易前台发起对话报价 → 填入交易要素 → 对手确认           │
│  │ → 生成成交单 → 数据同步至中后台                                   │
│  └──────────────────────────────────────────────┘                   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**IM询报价中的关键信息要素**：

| 要素 | 示例 | 说明 |
|------|------|------|
| 债券标识 | "21国开10"、"210210.IB" | 简称或代码均可 |
| 方向 | "出"、"收"、"bid"、"ofr" | 出=卖出，收=买入 |
| 价格 | "2.82%"、"净价99.5" | 收益率或净价报价 |
| 数量 | "5000万"、"5kw"、"5e" | 面值金额，常用简写 |
| 意图 | "询价"、"成交"、"撤了" | 询价/成交/撤销 |
| 期限 | "7D"、"14D"、"1Y" | 回购/资金交易常用 |

**QTrade AI语义识别机制**：

QTrade通过三层AI模型处理IM中的非结构化交易信息：

1. **文本分类层**：判断聊天内容是"闲聊"还是"讨论业务"
2. **意图识别层**：细分业务意图——询价、报价、成交、改标、撤标、头寸管理
3. **信息抽取层**：解析债券代码、价格、数量等关键要素，结构化为标准格式

> 技术参考：QTrade AI研究中心2021年在ACL会议发表多篇NLP论文，
> 涉及依存句法图卷积、类型感知记忆网络等关系抽取算法。

#### 2.3 路径B：X-Bond匿名点击成交

```
X-Bond 匿名点击成交机制：

  交易中心撮合引擎
  ┌──────────────────────┐
  │  Bid (买入)  │ Ask (卖出) │
  │  99.50/2.82% │ 99.55/2.81%│  ← 匿名双边报价
  │  99.48/2.83% │ 99.58/2.80%│
  └──────────────────────┘
         │ 点击即成交
         ▼
    匹配成功后揭示对手身份
```

- **X-Bond**：现券匿名点击业务，做市商/尝试做市机构提供匿名双边报价
- **X-Repo**：质押式回购匿名点击，支持自动选券
- **X-Swap**：利率互换匿名点击（与X-Bond整合为X-Trade）
- **X-Bargain**：匿名询价机制，支持匿名协商
- **债券篮子**：一篮子债券打包交易

#### 2.4 路径C：做市商点击成交

```
做市商点击成交流程：

  做市商双边报价引擎                    交易员
  ┌────────────────┐                     │
  │ Bid: 99.50     │◀── 做市商持续报价 ──│
  │ Ask: 99.55     │                     │
  │ 数量: 5000万   │                     │
  └────────────────┘                     │
         │                               │
         │◀──── 交易员点击买入 ──────────│
         ▼                               │
    即时成交，生成成交单                    │
```

- 做市商有义务持续提供双边报价（Bid/Ask）
- 报价必须有明确的价格和数量
- 交易员点击即成交，无需协商
- 适用于国债、政金债等流动性好的活跃券

#### 2.5 路径D：CFETS RFQ请求报价

```
询价方                           做市商/交易对手
  │                                  │
  │──── 1.发送RFQ ────────────────▶│  债券代码、方向、数量
  │                                  │
  │◀─── 2.回复报价 ────────────────│  价格/利率、有效期
  │                                  │
  │──── 3.接受报价/继续谈判 ───────▶│
  │                                  │
  │──── 4.确认成交 ───────────────▶│  双方确认
  │                                  │
```

- 在CFETS本币系统内直接发送RFQ
- 可同时向多个对手发送RFQ（多选询价）
- 对手在有效期内回复报价
- 适用于有明确交易意向但需要比价的场景

#### 2.6 CFETS对话报价（线下意向的线上化）

当交易双方通过IM达成口头意向后，需在CFETS系统内正式录入：

```
交易员A（发起方）                     交易员B（应答方）
  │                                      │
  │──── 1. 新建对话报价 ───────────────▶│
  │      填写: 债券代码/方向/价格/       │
  │            数量/结算日/结算方式       │
  │                                      │
  │◀─── 2. 对手接受/还价 ──────────────│
  │                                      │
  │──── 3. 确认成交 ───────────────────▶│
  │                                      │
  │     成交单生成，数据同步中后台         │
```

**对话报价中的交易要素**：

| 要素 | 现券买卖 | 质押式回购 | 债券借贷 |
|------|----------|------------|----------|
| 债券代码 | ✅ | ✅（质押券） | ✅（标的券） |
| 交易方向 | 买入/卖出 | 正/逆回购 | 借入/借出 |
| 价格 | 净价或收益率 | 回购利率(%) | 借贷费率(%) |
| 数量 | 面值金额 | 融资金额 | 标的券面值 |
| 结算日 | T+0/T+1 | 首次/到期结算日 | 起息/到期日 |
| 结算方式 | DVP | DVP | 券券交割 |
| 质押品 | — | 质押券列表 | 质押券(可选) |

#### 2.7 iDeal在询报价中的角色

CFETS iDeal是交易中心推出的官方合规IM工具，深度集成CFETS交易系统：

- **实名认证**：所有用户经CFETS实名认证，与机构交易员身份绑定
- **合规留痕**：所有沟通信息自动留痕，满足监管审计要求
- **交易辅助**：支持从IM沟通直接发起对话报价/RFQ，无需切换系统
- **做市报价推送**：做市商报价实时推送至IM窗口
- **一级分销**：支持iDeal分销功能，债券承销分销全流程线上化
- **与QTrade竞争**：2021年交易商协会规范IM工具后，iDeal与QTrade形成双寡头格局

## 三、特殊交易场景

### 1. 大额交易

- 单笔交易金额较大时，需分拆执行以降低市场冲击
- 系统需支持大额交易的分批下单与统一管理
- 需要算法交易支持（TWAP/VWAP等）

### 2. 跨市场交易

- 银行间市场与交易所市场间的跨市场交易
- 需处理不同市场的交易时间、结算规则差异
- 涉及不同托管机构间的债券转托管

### 3. 回购到期续做

- 回购到期后自动发起新的回购交易
- 系统需支持到期提醒与续做工作流
- 需要考虑质押品的滚动管理

### 4. 做市商双边报价

- 做市商需持续提供买卖双边报价
- 系统需支持自动报价策略
- 需实时监控持仓和风险敞口

## 四、交易时间

| 时段 | 时间 | 说明 |
|------|------|------|
| 开盘前 | 8:30 - 9:00 | 系统准备，查询行情 |
| 上午交易 | 9:00 - 12:00 | 主要交易时段 |
| 午间 | 12:00 - 13:30 | 休市 |
| 下午交易 | 13:30 - 16:30 | 主要交易时段 |
| 交易后处理 | 16:30 - 17:00 | 结算指令发送 |
| 夜间 | 17:00 之后 | 部分品种可延长交易 |

> **注意**：具体交易时间以 CFETS 公告为准，节假日安排另行通知。

## 五、对交易系统设计的启示

1. **流程自动化**：从询价到结算的流程需尽量自动化，减少人工干预
2. **合规前置**：交易前合规检查必须实时完成，不影响交易效率
3. **多模式支持**：需同时支持询价、点击成交、RFQ等多种交易模式
4. **实时风控**：交易过程中需实时监控风险敞口
5. **审计追踪**：所有操作需记录完整的审计日志
6. **异常处理**：需支持交易撤销、修改、结算失败等异常场景
