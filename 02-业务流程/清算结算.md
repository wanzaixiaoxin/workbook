# 清算结算

> 最后更新：2026-03-30

## 一、清算结算概述

### 清算与结算的区别

| 概念 | 说明 |
|------|------|
| **清算** | 计算交易双方的资金和债券应收应付数额 |
| **结算** | 实际完成资金划拨和债券过户 |

### 结算方式

| 方式 | 说明 | 使用场景 |
|------|------|----------|
| **DVP（券款对付）** | 债券和资金同时交割 | 主要结算方式 |
| **FOP（纯券过户）** | 先划转债券，后划转资金 | 较少使用 |
| **PAD（见券付款）** | 收到债券后付款 | 较少使用 |
| **DAP（见款付券）** | 收到资金后划券 | 较少使用 |

> **当前市场**：DVP 是银行间债券市场的主要结算方式，有效控制了结算风险。

### 结算周期

| 品种 | 常见结算周期 |
|------|-------------|
| 现券买卖 | T+0 或 T+1 |
| 质押式回购（首次） | T+0 或 T+1 |
| 质押式回购（到期） | 到期日结算 |
| 买断式回购 | T+0 或 T+1 |
| 债券借贷 | T+0 或 T+1 |

## 二、清算流程

### 现券买卖清算

```
交易成交
    │
    ▼
┌──────────────┐
│  清算计算     │
│  - 全价 = 净价 + 应计利息
│  - 应计利息计算
│  - 结算金额确定
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  结算指令生成  │
│  - 向CCDC/SHCH发送
│  - 包含交易要素
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  结算指令匹配  │
│  - 双方指令匹配
│  - 前提条件检查
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  DVP结算执行  │
│  - 债券过户
│  - 资金划拨
└──────────────┘
```

**关键计算**：

```
全价 = 净价 + 应计利息

应计利息 = 面值 × 票面利率 × 应计天数 / 全年天数

结算金额 = 全价 × 交易数量 / 100
```

### 回购清算

**首次结算**：
```
融入方收到：资金
融出方收到：质押债券
```

**到期结算**：
```
融入方支付：本金 + 利息
           到期利息 = 融资金额 × 回购利率 × 回购天数 / 365
融出方收到：本金 + 利息
质押债券解除质押，返还融入方
```

## 三、托管结算体系

### 双托管体系

```
银行间债券市场托管体系
├── 中债登（CCDC）
│   ├── 职责：国债、政策性金融债、企业债等
│   ├── 账户体系：一级托管（直接开户）
│   ├── 结算模式：全额逐笔结算（RTGS）
│   └── 网址：chinabond.com.cn
│
└── 上清所（SHCH）
    ├── 职责：短融、中票、同业存单、利率互换等
    ├── 账户体系：一级托管
    ├── 结算模式：全额结算 + 集中净额结算
    └── 网址：shclearing.com
```

### 账户结构

```
中债登账户体系
├── 甲类账户 —— 商业银行（可代理结算）
├── 乙类账户 —— 信用社、非银金融机构
├── 丙类账户 —— 非金融机构（需通过甲类代理结算）
└── 特殊机构账户 —— QFII等境外机构
```

| 渠道 | 说明 | 适用场景 |
|------|------|----------|
| **大额支付系统（HVPS）** | 央行运行的实时全额结算系统 | DVP资金划拨 |

| **备付金账户** | 在托管机构开立的资金账户 | 部分结算场景 |

## 五、结算失败处理

### 常见失败原因

| 原因 | 说明 | 处理方式 |
|------|------|----------|
| 资金不足 | 买方资金账户余额不足 | 补充资金或取消 |
| 债券不足 | 卖方债券账户余额不足 | 补充债券或取消 |
| 质押品不足 | 回购质押券不足 | 追加质押或取消 |
| 结算指令错误 | 要素填写错误 | 修改后重新提交 |
| 系统故障 | 结算系统异常 | 联系托管机构处理 |

### 结算失败的影响

- 影响交易对手方的资金/债券使用计划
- 可能触发违约条款
- 影响交易双方的信用关系
- 监管报告要求

## 六、对交易系统的要求

1. **结算指令自动生成**：成交后自动生成标准结算指令
2. **多托管机构支持**：需同时对接中债登和上清所的结算接口
3. **结算状态跟踪**：实时跟踪结算进度和状态
4. **异常预警**：结算失败或异常情况实时预警
5. **日终处理**：支持日终对账、头寸管理
6. **资金管理**：与内部资金管理系统联动
